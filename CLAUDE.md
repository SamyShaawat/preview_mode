# Preview Mode (`preview_mode`): project guide for Claude

Read this first. It records the owner's decisions and how work is done here, so a new session can continue without the old conversation. The design is in `docs/superpowers/specs/2026-11-02-preview-mode-design.md` and the task plan in `docs/superpowers/plans/2026-11-02-preview-mode.md`; they are binding, this file is the quick map.

## What it is

A free, open-source Odoo app (LGPL-3, OCA-style conventions, also listed free on the Odoo Store) that shows what a button click would create, change or delete, and where, before the user commits to it. A toggle button in the top bar turns Preview mode on and off. With it on, clicking a button that changes data opens a popup instead of acting. Nothing is saved during the preview. The user then confirms for real or goes back. Owner: Samy Mostafa Shaawat (GitHub `SamyShaawat`).

## Owner decisions (all binding)

- **Audience:** every user of every app. NOT accounting-only, NOT for specific users or apps. There is no per-user, per-app or per-button allow-list or deny-list and nothing to configure: once installed and the toggle is on, it works on EVERY button that changes data, in every app (core, Enterprise, third-party, custom), for every internal user, with nothing to configure. Two narrow exceptions (owner-approved 2026-11-05): a FIXED safety exclusion (`UNSAFE_MODELS`/`UNSAFE_PREFIXES` in `models/payload.py`: module install/upgrade, Settings save, ir.model/fields/view) because a savepoint cannot undo registry changes, and three OPTIONAL system parameters with safe defaults (`preview_mode.enabled`, the kill switch, default on, `False` hides the toggle and stops previews for everyone (session info `preview_mode_available` drives `isDisplayed` of the systray item, so a page reload is needed); `preview_mode.timeout` seconds, default 10; `preview_mode.max_records`, default 0 = no limit). There is no per-group, per-company or per-model setting (owner decision 2026-11-05). The journal-entry (Debit/Credit) view is just one extra view for accounting clicks.
- **Versions:** 16.0, 17.0, 18.0, 19.0, 20.0. **20.0 is the reference and default branch** (it was 19.0 until 2026-11-02): build there first. **The owner ordered the ports on 2026-11-10 (the old "prove it on 20.0 first" rule is lifted): one PR per version, all module tests must pass on that version's own Odoo, and 16.0 merges last.**
- **Community-based, works on Enterprise:** depends only on `base` and `web`. It must install and run when Odoo Enterprise is installed (`web_enterprise` changes the navbar and control panel). Enterprise source exists locally for 17.0, 18.0, 19.0 only.
- **Odoo.sh compatible (hard rule):** no external Python packages, no `requirements.txt`, no system or `subprocess` calls, no file writes outside Odoo storage, all state in the database (workers share no memory), no `readonly` routes, no dependence on `odoo.conf` options, no Enterprise-only code. Odoo.sh users add the repo as a git submodule named `preview_mode`.
- **Standard Odoo/OCA practice** for easy upgrade and maintenance: extend with `_inherit`, never edit core, Odoo naming, `_description`, everything prefixed `preview_mode`, user-facing strings translatable, minimal guarded patches only, the Python core identical across versions with every version difference isolated in a small `PORT:`-commented place.
- **License:** LGPL-3 (decided 2026-11-05, replaces OPL-1 and the paid-Store plan; text in `LICENSE`, copyright holder is the owner). "OCA style" means OCA conventions in the owner's own repo; a real OCA submission waits for a second maintainer. Accept outside pull requests only with a DCO sign-off. No `price` in the manifest.
- **Where the control lives:** a toggle button in the top bar (systray, top right, same place on Community and Enterprise). Click it to turn on, click again to turn off. Pressed look and accent colour while on, `aria-pressed`, tooltip, keyboard operable, remembered per user (`res.users.preview_mode_enabled`). The owner said "top of the page on the left or something"; the systray is the author's call (stable on 16 to 20). Ask the owner if they insist on the left.
- **Popup (design A, native Odoo look):** title `Preview: <button label>`; subtext `This is a preview. Nothing from this click has been saved yet.`; order: yellow warning banner (only yellow use), one-sentence summary, a "What will happen" table with columns What (New/Changed/Deleted, old value struck through then new) and Where (Odoo menu path like `Accounting > Accounting > Journal Entries`, or "Here, on this <record>"), then journal lines when a journal entry would be created. Footer left to right: primary button with the SAME label as the clicked button, then `Go back` (not Cancel). Header and footer fixed, middle scrolls. Native Odoo dialog, one accent `#714b67`, flat tables, no pills or emoji, long names wrap, numbers right-aligned on one line, RTL (Arabic) mirrors. A failing click shows `Confirming will fail: <message>` and Confirm stays clickable (the real run decides).
- **Only buttons that change data:** a click that would change nothing (smart buttons, Print, buttons that only open a wizard) runs normally, no popup. The server decides with the payload flag `show` (never `changes == []`).
- **Dirty form:** Odoo saves the user's own edits first as usual; the popup says "Nothing from this click has been saved yet".
- **After Confirm:** a toast lists what was created, each as a clickable link.
- **Icon:** `static/description/icon.png` (128x128) plus `icon.svg`: a white eye on Odoo purple with a click cursor in the iris. Checked on real Odoo 19 + `web_enterprise`.
- **README** must describe only what really exists (status line says what is built).

## How it works

`build_preview()` runs the clicked method inside a savepoint via `safe_run()` and always rolls back. Guards inside `safe_run`: commit and rollback are neutralised on the preview's cursor, sequences return the placeholder `(new)`, `send_email` is recorded not sent, outgoing `requests` calls are blocked, any extra DB connection (including cron/bus style `db_connect`) marks the preview incomplete, post-commit callbacks are dropped; thread-local, nest-safe, inert for other threads. A recorder hooked on `base` create/write/unlink AND `_write_multi` (Odoo delays writes: recomputed stored fields reach the DB only at flush, so `build_preview` calls `env.flush_all()` inside the savepoint) collects changes; queued `mail.mail` rows count as emails (once, even if also sent); values are shown formatted for the user (`models/formatting.py`). The preview runs under `SET LOCAL statement_timeout`. Client: the preview request carries `user.context`; if the preview call fails a confirmation dialog offers "Run without preview" or "Go back"; the popup has a Copy button (plain text) and an "estimate" note. It (ignore list `IGNORED_MODELS`/`IGNORED_FIELDS` lives only in `models/recorder.py`). `locate()` turns models into Odoo menu paths (visible menus only). The real run (after Confirm) records created ids in the transient model `preview.mode.created` (token in context, DB-backed, per-user rows, sudo-created and unreadable records never returned) for the toast links. Routes: `POST /preview_mode/run`, `POST /preview_mode/created`; never `call_button`, no `sudo`, not readonly. Client (built): wrap the button-click function (`doActionButton` in `action_service.js` on 16 to 19; on 20.0 it moved to `webclient/actions/action_plugin.js`, read it first), systray toggle, `web.Dialog` popup, toast.

## Repo, clones, databases

- GitHub: `SamyShaawat/preview_mode` (private). Branches `16.0 17.0 18.0 19.0 20.0` only; the module is the folder `preview_mode/` inside the repo (layout of 2026-11-10, what the Odoo Apps Store expects); community files, docs, CI and scripts are at the root. Default branch 20.0.
- Clones: one clone per version branch, each in `odoo-<V>/addons/preview_mode` of a matching Odoo checkout. The module is then at `addons/preview_mode/preview_mode`, so `odoo.conf` `addons_path` must include `<...>/odoo-<V>/addons/preview_mode`. Odoo.sh: its FAQ says the folder holding a submodule is detected as an addons folder, so a submodule whose root contains `preview_mode/` works. Machine-specific paths, database names and ports live in `CLAUDE.local.md` (git-ignored, not in the repo).
- Run Odoo from the checkout with its own venv (Python 3.12) and `odoo.conf`. Use a database that is not the owner's own, and a free HTTP port for tests that start HTTP. A running server caches the module manifest: restart it and press "Update Apps List" after code changes.
- Odoo 19 does not load demo data from the CLI unless `--with-demo`; 16 to 18 do by default.
- Tests: from `odoo-<V>`: `./odoo-venv/bin/python odoo-bin -c odoo.conf -d pm<NN> -u preview_mode --test-tags /preview_mode --http-port=<free port> --stop-after-init`; expect `0 failed, 0 error(s) of N tests`. Odoo 20 API notes: config parameters are read with `get_str/get_int/get_float` (set with `set_str`), not `get_param`. The mail test needs the `mail` app: run it on a scratch DB, `-d pm20mail -i mail,preview_mode --without-demo=all`.

## Workflow rules (this project only)

- Every task goes through a pull request: topic branch `<type>/<series>-<topic>` (feat, fix, docs, port, chore; NEVER `19.0/...`, a branch named `19.0` blocks it), base = the matching version branch, title `[20.0] ...`, body states the base branch and that the topic branch is deleted after merge. Squash merge only; GitHub deletes merged branches. Version branches are protected (PR required). See `CONTRIBUTING.md` and `.github/pull_request_template.md`.
- **Ports (all five versions done 2026-11-10).** A fix lands on 20.0 first and is ported to the others. Ports are separate PRs, one per version, and must pass ALL module tests on that version's own Odoo before merging. Never leave a red version; fix it first. Known port differences: the mail-server connect method name is detected inside the guard (`_connect__` on 19 and 20, `connect` on 16 to 18), so no rename is needed; route type `jsonrpc` (19, 20) vs `json` (16 to 18); ACL file `ir.access.csv` (20) vs `ir.model.access.csv` (16 to 19); `user_writeable` field parameter (20) vs `SELF_WRITEABLE_FIELDS`; `has_access` vs the older rights+rule pair; no walrus `:=` (Odoo 16 supports Python 3.7).
- The owner says "merge all" when they want open PRs merged; otherwise open the PR and stop. Merging, like porting, waits for the owner's word. Never merge a version that fails tests.
- No Claude attribution lines (no Co-Authored-By, no "Generated with Claude Code") in commits or PRs.
- Tasks run with subagent-driven development: a fresh implementer per task, an independent reviewer per task, scoped re-reviews of fixes (max 5 rounds). Stacked task branches conflict after a squash merge: branch each task from the latest `20.0` instead, or `git rebase --onto origin/20.0 <old-base> <branch>`.

## Status (2026-11-10)

All five versions (20.0, 19.0, 18.0, 17.0, 16.0) are ported, merged and tested on their own Odoo, with the Apps Store layout. Release tags planned: `20.0-v1.0.1`, `19.0-v1.0.0`, `18.0-v1.0.0`, `17.0-v1.0.0`, `16.0-v1.0.0` (the older `v1.0.0` tag is the first 20.0 release); `CHANGELOG.md` lists what is in each. This branch is 20.0, version 1.0.1. 20.0 is the reference. Enterprise: verified on 19, 18 and 17 (`docs/enterprise-verification.md`); not verified on 20 and 16 (no source here). Raw SQL writes are detected by `models/rawwrites.py` (PostgreSQL `pg_stat_xact_user_tables` counters before and after the click; a table that moved without a matching recorder entry, after allowing for ignored models, many2many link tables and foreign key cascades, makes the preview incomplete).

Known gaps: a raw UPDATE on a table the ORM also wrote in the same click is not seen; the timeout only bounds SQL statements; `display_name` of a created record is stored at create time and can be stale; when no visible menu matches a model, Where falls back to the model's description (so a transfer row can show the model name).
